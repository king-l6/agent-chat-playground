SSE 拆包怎么说清楚

说不清这段，先别钻 tool 多轮。对着浏览器 Network 里的 chat 响应，把下面稿子说一遍。

30 秒口述版（背这个骨架）

后端用 text/event-stream，不是一次返回完整 JSON，而是持续往连接里写小块数据。 每条事件长这样：data: {JSON}\n\n，空行 \n\n 表示一条事件结束。 前端拿到的是 ReadableStream，reader.read() 每次只读到一段二进制，切包边界和网络 chunk 对不齐，所以要： 1）TextDecoder 转成字符串拼进 buffer； 2）按 \n\n 切开，完整的事件拿去处理，最后半截留在 buffer 下次再拼； 3）从事件里找出 data: 行，去掉前缀，JSON.parse 成 SseEvent，回调给 UI 追加文字或更新工具卡片。 点停止就 AbortController.abort()，中断这条流。

五步拆开记

  1. 协议：SSE，不是一次性 JSON。
  2. 格式：data: {...}\n\n，空行分隔事件。
  3. 读流：ReadableStream + reader.read()。
  4. 拆包：buffer 拼接 → split('\n\n') → pop 半截。
  5. 落地：JSON.parse → onEvent → UI 更新；停止用 AbortController。

为什么要 buffer（一句话 + 例子）

网络 chunk 边界和事件边界往往对不齐。若直接 parse 半截，会挂；所以 完整事件立刻处理，半截先存着。 

data: {"type":"text_delta","delta":"你"}\n\n
data: {"type":"text_de   ← 这条被砍半了，留在 buffer
